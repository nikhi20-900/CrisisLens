# CrisisLens AI — Shared Domain Contracts & Data Architecture

## Conceptual Flow & Entity Relationship

```
REPORT (Raw Multimodal Inputs)
  ↓ [AI Evidence Analysis Layer]
EVIDENCE (Confidence-Scored Features)
  ↓ [Incident Fusion Layer]
EVIDENCE LINK (Spatial, Temporal & Semantic Matching)
  ↓
INCIDENT (The Evolving Real-Time Situation Object)
  ├── IMPACT (Casualties, Infrastructure Damage, Hazard Radius)
  ├── NEED (Rescue, Medical, Food, Water, Shelter, Transport)
  ├── INCIDENT SNAPSHOT (State Changes & "What Changed?" Diff Engine)
  └── ACTION PLAN (Decision Support & Explainable Resource Recommendation)
             ↓
          RESOURCE (Boats, Ambulances, Transit Busses, Pumps, Teams)
```

## Shared Schemas Overview

All 4 members **must** adhere strictly to these 9 core contracts. Neither frontend nor backend components may invent ad-hoc JSON fields.

### 1. `Report` (Raw Disaster Evidence)
The ingestion boundary representation.
- `report_id`: Unique identifier (e.g. `"R-001"`).
- `text`: Raw text from citizen, 911 dispatch, radio, or sensor.
- `media`: Array of media objects (`media_id`, `media_type`, `url`, `caption`).
- `location`: Optional reported coordinate (`lat`, `lng`, `address`, `radius_meters`).
- `source`: `"citizen"`, `"emergency_call"`, `"traffic_camera"`, `"drone"`, `"field_agent"`, `"sensor"`.
- `timestamp`: UTC ISO-8601 timestamp.

### 2. `Evidence` (Structured AI Knowledge)
Extracted by Member 1 from raw `Report`.
- `evidence_id`: String (e.g. `"EV-001"`).
- `report_id`: Link to parent report.
- `disaster_type`: `"flood"`, `"fire"`, `"earthquake"`, etc.
- `severity`: `"low"`, `"medium"`, `"high"`, `"critical"`.
- `people_affected`: Integer count of people directly endangered or impacted.
- `needs`: Array of extracted relief categories (`"rescue"`, `"medical"`, etc.).
- `access_status`: `"open"`, `"partially_blocked"`, `"blocked"`, `"submerged"`, `"unknown"`.
- `location`: Standardized geographic coordinates.
- `urgency`: `"low"`, `"medium"`, `"high"`, `"critical"`.
- `confidence`: Dictionary of field-level confidence scores (0.0 - 1.0).
- `raw_report`: Preserved original report object.

### 3. `EvidenceLink` (Incident-Evidence Relation)
Created by Member 2 when linking evidence to an incident.
- `link_id`: Unique link identifier (e.g. `"EL-001"`).
- `incident_id`: Foreign key to target `Incident`.
- `evidence_id`: Foreign key to source `Evidence`.
- `similarity_score`: 0.0 - 1.0 confidence.
- `link_rationale`: Human-readable explainable reason (spatial/temporal/semantic).

### 4. `Impact` (Incident Assessment)
- `casualty_count`: Estimated injuries/deaths.
- `displaced_count`: Number of evacuated/homeless individuals.
- `trapped_count`: People actively stranded.
- `infrastructure_damage`: Key-value map (e.g. `{"bridge": "submerged", "power": "offline"}`).
- `hazard_radius_meters`: Impact radius.

### 5. `Need` (Operational Requirements)
- `need_id`: String (e.g. `"ND-001"`).
- `type`: `"rescue"`, `"medical"`, `"food"`, `"water"`, `"shelter"`, `"transport"`.
- `urgency`: `"low"`, `"medium"`, `"high"`, `"critical"`.
- `confidence`: 0.0 - 1.0.
- `status`: `"unmet"`, `"in_progress"`, `"met"`, `"cancelled"`.
- `quantity`: Number of items or people involved.

### 6. `Resource` (Response Capabilities)
- `resource_id`: String (e.g. `"RES-01"`).
- `name`: Display name (e.g. `"Water Rescue Boat Alpha"`).
- `resource_type`: `"rescue_boat"`, `"ambulance"`, `"evacuation_bus"`, etc.
- `location`: Current coordinates.
- `availability`: `"available"`, `"assigned"`, `"in_transit"`, `"depleted"`.
- `capacity`: Integer capacity.
- `current_assignment`: Incident ID if deployed.

### 7. `ActionPlan` (Response Recommendation)
Generated by Member 3; verified by human responder.
- `action_id`: String (e.g. `"ACT-001"`).
- `incident_id`: Target incident.
- `priority_score`: 0.0 to 100.0 explainable score.
- `priority_level`: `"low"`, `"medium"`, `"high"`, `"critical"`.
- `priority_rationale`: Array of explanatory bullet points.
- `recommended_resources`: Array of matched `Resource` objects.
- `resource_rationale`: Explainable matching justification.
- `verification_status`: `"pending"`, `"approved"`, `"rejected"`, `"edited"`.
- `verified_by`: User ID of human responder.
- `responder_notes`: Optional human verification feedback.

### 8. `IncidentSnapshot` ("What Changed?" Engine)
Generated by Member 2 upon every meaningful update.
- `snapshot_id`: String (e.g. `"SNAP-001"`).
- `incident_id`: Foreign key.
- `timestamp`: UTC timestamp.
- `delta_summary`: Array of diff strings, e.g.:
  - `"+5 people affected"`
  - `"+Rescue need detected"`
  - `"Road status changed: open -> blocked"`
- `summary`: Concise human-readable situation synopsis.

### 9. `Incident` (Core Incident Object)
Aggregates all contributing evidence links, needs, impacts, active action plans, contradiction flags, and snapshot history.
